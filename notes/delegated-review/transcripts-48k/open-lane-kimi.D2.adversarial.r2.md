1. **`kernel/src/user/install_service.rs` — `spawn_surveyor` can never return `None`, so the failure branch is dead and the real failure mode is a silent boot hang.** The function's only exit is `Some((table_msg[0], table_msg[1], table_msg[2]))` after two bare `ipc_recv(report)` calls with no timeout, so the caller's `"(survey timed out or failed)"` string is unreachable — the author clearly believed a timeout existed, and none does. If the surveyor faults (it is brand-new code parsing arbitrary, possibly corrupt MBR/GPT structures) or its protocol sends fewer than two messages, the boot blocks forever *before* the prompt with zero console output. The module's own doc promises that every path "continues to the ordinary boot" and that waits are bounded so a headless machine reaches a prompt; this change adds an unbounded wait that violates exactly that property.

2. **`kernel/src/user/install_service.rs` — the module doc's BUGS entry now describes a defect this commit fixes.** The entry "It checks for nife and for nothing else… Naming what is already on it is `disk_surveyor`'s job, and `…the-install-offer-should-say-what-is-already-on-the-disk.md` is the proposal for it" is precisely what milestone 551 implements, yet it is left standing as an open BUG. In a tree where the design records are part of the deliverable, the record now lies about the system it ships with.

3. **`kernel/src/user/install_service.rs` — the doc's capability table and "two confined programs" framing omit the surveyor.** The surveyor is a third confined program this module spawns, and it holds the disk endpoint (`Rights::WRITE`) and the read-write shared page *before* the person answers — by the table's own definition, a program that "can destroy: that disk." The doc's load-bearing argument ("the authority to wipe the disk does not exist until the answer does") is never extended to cover it; the pre-existing `ROLE_SURVEY` at least has its no-endpoint-for-entropy justification recorded, and the surveyor gets none.

4. **`kernel/src/user/install_service.rs` — the EXAMPLES block no longer matches the program's output.** It still shows `TARGET: the NVMe disk attached to this machine, 1073741824 bytes.` with no parenthetical, but every path through the new code appends one (` (has partitions, no nife)`, ` (no surveyor available)`, etc.). The recorded example of the most safety-critical dialogue in the system is stale.

5. **`kernel/src/user/install_service.rs` — `format_disk_description` never consults `F_MBR` (nor `F_BACKUP`, `F_NAMES`, `F_ROSTER`, all defined here "matching `disk_surveyor.rs`").** A disk carrying an MBR partition table and no GPT — the classic Windows/Linux-disk case the milestone exists to warn about — has `F_PRIMARY` clear and so falls through to `"(unpartitioned or unreadable)"`, i.e. the offer still describes an occupied disk as empty. Half the duplicated flag vocabulary is unused, which strongly suggests the formatting half of the milestone is unfinished.

6. **`kernel/src/user/install_service.rs` — the `F_NIFE` arm of `format_disk_description` is unreachable.** A disk already carrying nife is caught earlier by the installer's `ROLE_SURVEY` (`R_ALREADY` → early return), so the surveyor is never spawned in that case and `"(already has nife installed)"` can never be printed. Dead code, and a sign the two surveys' division of labour was never reconciled.
