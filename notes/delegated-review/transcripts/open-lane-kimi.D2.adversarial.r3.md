1. **`kernel/src/user/install_service.rs` — `format_disk_description` never consults `F_MBR` (or `F_BACKUP`).** The "has partitions" verdict requires `F_PRIMARY`, i.e. a GPT primary header. A disk partitioned with a plain MBR — the shape of a typical Windows or older Linux install — falls through to `" (unpartitioned or unreadable)"`, so the single sentence a person reads before typing `INSTALL` tells them a disk full of data is empty. That is exactly the harm this milestone exists to remove (the module's own BUGS entry: "A disk carrying Windows, or a Linux root, looks exactly like an empty one from here… A person who says yes to the question loses that disk"). The constant `F_MBR` is defined and never used; no compiler or test can see that the wrong flag gates the warning — only a human comparing the flag set to the strings can.

2. **`kernel/src/user/install_service.rs` — `spawn_surveyor` cannot fail, so its error path is a lie and its failure mode is a hung boot.** The body ends in an unconditional `Some(...)` after two blocking `ipc_recv(report)` calls with no timeout; the `" (survey timed out or failed)"` branch at the call site is unreachable. If the surveyor crashes, fails to spawn its payload, or sends only one of the two expected messages, the boot blocks forever at this point — before the prompt, before the rest of the boot. The module header documents the opposite property for this offer ("The wait is bounded, so a stick booted on a machine with no console reaches the prompt instead of hanging"), and unlike the installer's survey this pass is purely informational, so an unbounded boot hang on it is a robustness regression introduced by an optional nicety.

3. **`kernel/src/user/install_service.rs` — a surveyor verdict of `F_NIFE` doesn't stop the offer.** If the surveyor reports nife on the disk, `format_disk_description` says "(already has nife installed)" but `offer()` proceeds to the prompt anyway, and typing `INSTALL` wipes the disk. Policy elsewhere in this file is absolute: "A machine that already carries nife is never offered an install again." If the surveyor's `F_NIFE` is worth printing it is worth gating on; as written, the branch is either dead code (the two surveys always agree) or a warning attached to an offer that should never have been made.

4. **`kernel/src/user/install_service.rs` — the in-tree design record now contradicts the code.** The module doc comment's BUGS list still contains "It checks for nife and for nothing else… Naming what is already on it is `disk_surveyor`'s job, and `…/the-install-offer-should-say-what-is-already-on-the-disk.md` is the proposal for it", and the EXAMPLES transcript still shows the old bare `TARGET:` line with no description. This commit *is* that proposal's implementation, yet the record — explicitly part of the deliverable in this repository — still describes the milestone as unimplemented and shows output users will no longer see.
