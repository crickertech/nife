1. **kernel/src/user/install_service.rs — the module's own documentation is now contradicted by the code it documents.** The `# BUGS` entry still says "**It checks for nife and for nothing else**" and points to `the-install-offer-should-say-what-is-already-on-the-disk.md` as an open proposal — but this commit is that proposal's implementation. The `# EXAMPLES` block still shows the old `TARGET:` line with no description; the header still says "the **two** programs that carry it out" (there are now three spawned programs); the "When the offer is made" list and the confinement table omit the surveyor entirely, including the safety argument for why a process holding the disk endpoint *before* the confirmation cannot write (the installer survey has the "no entropy" argument; the surveyor gets no such treatment). In this tree the prose is part of the deliverable, and the BUGS list is how a reader learns what to trust — landing the feature without touching it leaves the file actively misleading.

2. **design/roadmap — no design record changes accompany a commit titled "Implement milestone 551".** The only file touched is kernel code. The proposal the module itself references (`design/roadmap/proposals/the-install-offer-should-say-what-is-already-on-the-disk.md`) presumably still reads as pending, and any roadmap entry for 551 remains unchecked. Since design records and the roadmap are treated as part of the deliverable, the milestone is only half-landed.

3. **kernel/src/user/install_service.rs — `spawn_surveyor` has no failure path, so the error handling in `offer()` is dead code and its message is false.** Setup failures `expect`-panic, and the function then blocks in two unconditional `ipc_recv`s and always returns `Some`. The `else` arm printing `" (survey timed out or failed)"` can never run, and there is no timeout: if the surveyor faults or sends only one of the two expected messages, the boot hangs forever in front of the prompt with no output — precisely the scenario the message claims to describe. Either implement a bounded wait (this module already has `PATIENCE` as precedent) or drop the `Option` and the fallback string.

4. **kernel/src/user/install_service.rs — the `F_NIFE` arm of `format_disk_description` is unreachable, and the disk is now surveyed twice.** `offer()` returns early when the installer's `ROLE_SURVEY` reports `R_ALREADY`, before the surveyor is ever spawned, so " (already has nife installed)" can only print if the two nife checks disagree. Meanwhile every installable boot now probes the disk with two sequential spawned processes doing overlapping work. Either let the surveyor's verdict replace the installer's survey (one probe, one source of truth) or delete the dead branch and the flag.

5. **kernel/src/user/install_service.rs — `format_disk_description` ignores `F_MBR` (and `F_BACKUP`), so MBR-partitioned disks are misdescribed.** A disk with an MBR partition table — the classic Windows layout the old BUGS entry explicitly worried about destroying — has neither `F_PRIMARY` nor `F_NIFE` set, so it falls through to `" (unpartitioned or unreadable)"`. That is exactly the disk this milestone exists to warn about, and a person reading "unpartitioned" may type INSTALL believing the disk is empty.

6. **kernel/src/user/install_service.rs — the new TARGET line can contradict itself.** `asked` always prints `{size_bytes} bytes` from the kernel's own NVMe identify, then may append `" (disk size unreadable)"` when the surveyor's `F_SIZE` is clear — the sentence states the size and denies knowing it. Likewise "unpartitioned or unreadable" conflates two distinct findings. The module itself calls this "the single most load-bearing sentence a stranger reads"; it must not be self-contradictory.

7. **kernel/src/user/install_service.rs — `F_ROSTER`, `F_MBR`, `F_BACKUP`, and `F_NAMES` are defined but never used.** Private unused `const`s trip `dead_code` warnings (a build failure if the kernel denies warnings), and their presence suggests the description was meant to use the surveyor's richer results — `F_NAMES` in particular is what would let the offer actually *name* what's on the disk — but was cut without removing the constants.

8. **kernel/src/user/install_service.rs — `use block_roster;` is a redundant single-component import.** The crate is already reachable via the extern prelude and every use below is fully qualified (`block_roster::Device`, etc.); clippy flags this (`single_component_path_imports`) and it matches none of the file's other imports.
