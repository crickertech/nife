# 2026-09-21, milestone 541 (a timed window that excludes preemption). Every row here moved, and
# two different causes are mixed in this save, which is why they are separated rather than left to
# a reader to guess at:
#
#   - `map_new` is the intended change. It masks interrupts across its timed window, so the row no
#     longer records whether a scheduler tick happened to land in 250 microseconds. Before this it
#     read 180,604 or 228,356 on x86_64 depending only on the phase an unrelated code-size change
#     left the timer in, a 26.4% swing over a byte-identical map path. It now reads the same number
#     either way. See design/roadmap/541-a-timed-window-that-excludes-preemption.md.
#   - **Every other row moved because the kernel grew**, not because anything on its path changed:
#     this milestone adds a per-core preemption counter (`cpu::PerCpu::preemptions`) and one relaxed
#     increment in `sched::count_preemption`, and icount counts drift across builds when live code
#     is added at all (the module header in kernel/src/bench.rs says why). The moves are 0.0% to
#     0.3% and in both directions, with `spawn_reap` the outlier at +2.3% on x86_64 and inside the
#     tripwire on all three. Nothing here is a claim that a path got faster or slower.
#
